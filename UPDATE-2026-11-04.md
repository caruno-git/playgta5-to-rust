# Source update: 2026-11-04

Author: carunodev @stfu

This update carries the current translated Rust source and repeatable regression
tests. It includes no compiled engine, original WASM/JavaScript, shaders, saves,
or game assets. The existing README, license, standalone workspace manifests,
and portable input preparation remain unchanged.

## Changes

- Correct four minimap fog-of-war shader pass indices against the independently
  checked `im.fxc` contract. Other shader pass users keep their existing indices.
- Install the cloth-instancing task's upload/cancel callbacks and temporary
  allocator. A native fixture executes the original task and real buffer-unlock
  method: the original drops the queued upload, while the fixed task delivers
  the exact changed bytes, offset, and length. This does not resolve the separate
  stretched player-model geometry defect.
- Preserve three SIMD conversion barriers used to avoid the earlier LLVM
  WebAssembly conversion-selection failure.
- Initialize the minimap HideFoW default from the nonblocking current start mode during
  fresh phase-eight initialization. Reinitialization and later script overrides
  remain covered by tests, with fog-data canaries unchanged.
- Add a resize/shutdown candidate that clears all six constant-buffer stage
  caches before the first unbind. Native tests execute the actual stage setters
  and clear helpers and verify freed bindings are not forwarded. Full shutdown,
  fullscreen transitions, and live gameplay acceptance remain unproven for this
  candidate; this update does not establish that all crashes are resolved.
- Make Rust panic diagnostics copy at most 64 KiB out of shared memory before
  decoding UTF-8. Invalid ranges and decoder failures retain bounded diagnostic
  evidence, and the original trap still propagates. The optional diagnostic
  output directory must be new, and AST comparison protects code outside the
  diagnostic callback.

## Tests from a source checkout

Python 3.9 or newer runs these regression tests. The native tests also require
`rustc` on PATH; they report explicit skips when it is unavailable. Node.js 18
or newer with its built-in test runner and the locked Acorn dependency runs the JavaScript
tests. From the repository root:

```text
npm ci --prefix tools --ignore-scripts
python -m unittest discover -s tools -p "test_*fixes.py"
python -m unittest discover -s tools -p "test_*delivery.py"
node --test tools/browser_adapter.test.cjs tools/test_shader_pass_contract.cjs
git diff --check
```

Publication verification on Windows passed 38 transformation/provenance tests,
six native delivery tests, and ten JavaScript tests. Two JavaScript integration
checks reported their missing-input prerequisites explicitly. No complete
engine build, browser run, fullscreen test, or deployment was performed for
this source publication.

`tools/testdata/provenance.json` records portable source paths and SHA-256 hashes
for four exact pre-transform Rust function files and two small ABI declaration
excerpts. These fixtures let the transformation and native regression tests run
without the unpublished original generated trees. The tests also inspect the
current tracked `linked/generated` implementation.

The complete adapter AST integration test additionally needs the original
`inputs/game.js` or `PLAYGTA5_JS` override, plus prepared
`linked/browser/game.js` and `linked/browser/memory-config.json`. The core
shared-memory, UTF-8, range, decoder-fallback, and trap tests run without those
files. Preparing the adapter artifacts enables the integration check on the
next test run.

The independent shader contract check needs the exact original `im.fxc`,
SHA-256 `5fb9c81b98186b81186159302b027443077ebc5d311644b062e532c2d7b60700`.
Supply it as an argument or set `PLAYGTA5_IM_FXC`:

```text
node tools/test_shader_pass_contract.cjs path/to/im.fxc
```

## Engine build inputs

Use the existing [README](README.md), [input preparation](Prepare-Inputs.ps1),
and [Linux build notes](BUILD-LINUX.md). The full WASM64 build still requires
the original matching `inputs/game.wasm`, generated memory segments, Rust and
its matching `rust-src`, and the toolchain configuration documented there.
Browser packaging also needs the original JavaScript and resulting memory
configuration. A Linux-hosted full build remains unverified.

`PLAYGTA5_WASM` and `PLAYGTA5_JS` overrides are preserved. Translation keeps the
`WAT` override and portable `inputs/game.wat` default; generating WAT requires
the original WASM input and a suitable converter. The original engine-image
comparison additionally requires the separate `inputs/va.bin` reference.
Serving the browser result requires the matching original loader, workers,
shaders and assets, cross-origin-isolation headers, and a browser supporting
shared WASM64 memory. The build does not produce a native game executable.
