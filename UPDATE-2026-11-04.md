# Rendering and runtime changes — November 4, 2026

Author: carunodev @stfu

This changelog describes the first group of rendering and runtime fixes
published on November 4. Later fixes from the same day are documented in the
[readback lifetime](UPDATE-2026-11-04-READBACK.md),
[grass-buffer reuse](UPDATE-2026-11-04-GRASS-POOL.md) and
[SIMD zero-load](UPDATE-2026-11-04-SIMD-ZERO-LOADS.md) notes.
The [README](README.md) covers the current release and installation.

## Changes

- **Minimap rendering:** corrected four fog-of-war shader pass indices against
  the original `im.fxc` shader contract. Other shader pass indices are unchanged.
  The initial HideFoW value now follows the current start mode without blocking
  fresh phase-eight initialization. Tests cover reinitialization, later script
  overrides and preservation of surrounding fog data.
- **Cloth uploads:** installed the cloth-instancing task's upload/cancel
  callbacks and temporary allocator. The original task could change CPU data
  without queuing its GPU upload; the corrected task submits the exact bytes,
  offset and length. The separate numerical cloth corruption was addressed by
  the later [SIMD correction](UPDATE-2026-11-04-SIMD-ZERO-LOADS.md).
- **SIMD compilation:** retained three conversion barriers that avoid the
  earlier LLVM WebAssembly instruction-selection failure.
- **Resize and shutdown:** clear all six constant-buffer stage caches before
  the first unbind so freed bindings are not forwarded to the GPU worker.
  This change's native regression tests cover the stage setters and clear
  helpers. The later [readback lifetime correction](UPDATE-2026-11-04-READBACK.md)
  documents the subsequent fullscreen runtime checks.
- **Panic diagnostics:** copy at most 64 KiB from shared memory before decoding
  UTF-8. Invalid ranges and decoder failures produce bounded diagnostics, and
  the original trap still propagates. Diagnostic output requires a new directory;
  an AST comparison checks that unrelated adapter code is preserved.

## Reproducing the regression tests

The focused tests require Python 3.9 or newer. Native execution tests also
require `rustc` on PATH and report a skip when it is unavailable. JavaScript
tests require Node.js 18 or newer and the locked Acorn dependency.

From the repository root:

```text
npm ci --prefix tools --ignore-scripts
python -m unittest discover -s tools -p "test_*fixes.py"
python -m unittest discover -s tools -p "test_*delivery.py"
node --test tools/browser_adapter.test.cjs tools/test_shader_pass_contract.cjs
```

The November 4 source-publication checks passed 38 transformation/provenance
tests, six native delivery tests and ten JavaScript tests on Windows. Two
JavaScript integration checks reported missing external inputs. Those checks
did not include a complete engine build or browser run; later runtime results
are recorded in the linked change notes.

[Fixture provenance](tools/testdata/provenance.json) records relative source
paths and SHA-256 hashes for four exact pre-transform Rust functions and two
small ABI declaration excerpts. The fixtures make the regression suite
independent of the full original generated tree. Tests also inspect the tracked
`linked/generated` implementation.

## Optional integration inputs

The complete adapter AST integration test requires the original
`inputs/game.js` or a `PLAYGTA5_JS` override, together with generated
`linked/browser/game.js` and `linked/browser/memory-config.json`.
Shared-memory, UTF-8, bounds, decoder-fallback and trap tests run without them.

The independent shader-contract test requires the original `im.fxc` with SHA-256
`5fb9c81b98186b81186159302b027443077ebc5d311644b062e532c2d7b60700`.
Its path can be passed directly or supplied through `PLAYGTA5_IM_FXC`:

```text
node tools/test_shader_pass_contract.cjs path/to/im.fxc
```

## Building the engine

The [build overview](README.md), [input preparation script](Prepare-Inputs.ps1)
and [Linux build guide](BUILD-LINUX.md) describe the full WASM64 build. It requires
the matching original WASM, generated memory segments, Rust and its matching
`rust-src`. Browser adapter generation also requires the original JavaScript
and the packager's memory configuration. A full build hosted on Linux has not
been verified.

`PLAYGTA5_WASM` and `PLAYGTA5_JS` can override the original input paths.
Regeneration accepts `WAT` or the default `inputs/game.wat`; producing that WAT
requires the original module and a suitable converter. Independent engine-image
comparison additionally requires `inputs/va.bin`.

The build output runs in a browser with shared WASM64 memory and the required
cross-origin-isolation headers. The matching loader, workers, shaders and
original game data are needed to load the world.
